# Translating Decoy

There are two things to translate: the **app interface** and the **README**. Both are plain text, so a machine
translation (Gemini, ChatGPT, DeepL, ...) followed by a quick human check works well.

Most of the existing translations were produced this way and have not been reviewed by native speakers. If you spot a
wrong or awkward phrase, fixing it is a small pull request (edit the value in `src/locales/<code>.json`).

## 1. The app interface

Every language is one JSON file in [`src/locales`](../src/locales). The file name is the language code
(`en.json`, `de.json`, `pt-BR.json`, `zh-CN.json`, ...). `ru.json` is the reference: it always has every key.

No code changes are needed. Drop the file in, rebuild, and the language appears in **Settings → Language** (the list
is searchable, also by English name). A missing key falls back to English, then Russian, so a partial translation
never breaks the app. Only `en` and `ru` are part of the main bundle; every other language is a small separate file
that is loaded when it is selected.

Text is drawn with Inter plus the fonts that ship with Windows 10/11 (Nirmala UI, Ebrima, Leelawadee UI, Gadugi,
Segoe UI Historic, ...), which cover every script the app currently supports. If a character shows up as an empty box,
open an issue with the language and the Windows version.

### Steps

1. Copy the whole content of `src/locales/en.json` (or `ru.json`).
2. Send it to your translator with the prompt below.
3. Save the answer as `src/locales/<code>.json` — **UTF-8 without BOM**.
4. Validate it:

   ```bash
   npm run check-locales
   ```

   The script reports invalid JSON, missing or unknown keys and any `{placeholder}` that was changed.

### Prompt

```
Translate the values of this JSON file into <LANGUAGE> for a desktop app UI (Decoy, a small Windows tool that
keeps a stand-in game process running so Discord shows a game as being played).

Rules:
- Return ONLY valid JSON, no markdown fences, no comments.
- Keep every key exactly as it is. Translate only the values.
- Do NOT translate or change placeholders in curly braces: {n}, {name}, {date}, {names}, {id}, {done}, {total}, {max}.
  Keep them exactly; you may move them to fit the grammar of the language.
- Keep "exe", "ID", "Discord", "Windows", "Decoy" untranslated.
- Keep UI strings short; buttons and tags must stay compact.
- "_meta.name" must be the language's own name in its own script (for example "Deutsch", "日本語", "العربية").
  For right-to-left languages add "rtl": true inside "_meta".
- "decoy" means a harmless stand-in program, not malware.

JSON:
<paste the file here>
```

### Rules for a locale file

- `_meta.name` is the language's own name, shown in the language list.
- `_meta.rtl` is `true` for right-to-left languages (Arabic, Hebrew, Persian, ...).
- Placeholders such as `{n}` must be kept as they are; you may move them inside the sentence.

## 2. The README

Translated READMEs live in `docs/i18n/README.<code>.md`. Every README starts with a language bar between the
`<!-- LANGUAGES:START -->` and `<!-- LANGUAGES:END -->` comments. **Do not write the bar by hand:** it is generated.

After adding or changing a translated README, run:

```bash
npm run readme-langs    # rewrites the language bar of every README (and fixes relative GitHub links)
npm run check-readmes   # verifies the bars and that every relative link and image exists
```

The bar shows the ten most spoken languages in a row and everything else in a collapsible list; the names come from
`_meta.name` in the locale files, so a README only needs the matching `src/locales/<code>.json`. To change which
languages are in the top row, edit `TOP` in `scripts/update-readme-langs.mjs`.

### Prompt

```
Translate this README.md into <LANGUAGE>.

Rules:
- Return ONLY the translated Markdown.
- Keep the structure, headings order, tables, badges, HTML comments and code blocks unchanged.
  Do not translate code, commands, file names, paths or URLs.
- Keep "Decoy", "Discord", "Tauri", "Rust" and other product names as they are.
- The file will be saved in docs/i18n/, two folders below the repository root, so make relative links work from
  there: "LICENSE" becomes "../../LICENSE", "CONTRIBUTING.md" becomes "../../CONTRIBUTING.md",
  "docs/TRANSLATING.md" becomes "../TRANSLATING.md", "src/locales" becomes "../../src/locales",
  the image "app-icon.png" becomes "../../app-icon.png" and "docs/screenshots/x.jpg" becomes "../screenshots/x.jpg".
- Translate the alt text of images and the captions under the screenshots.
- Anchors to headings must match the translated headings.
- Keep the two lines "<!-- LANGUAGES:START -->" and "<!-- LANGUAGES:END -->" exactly as they are and put nothing
  between them (the language bar is generated by a script afterwards).

README:
<paste README.md here>
```

The two files of a new language (`src/locales/<code>.json` and `docs/i18n/README.<code>.md`) use the same code.
Then run `npm run readme-langs`: it adds the language to the bar of every README so they all link to each other.
